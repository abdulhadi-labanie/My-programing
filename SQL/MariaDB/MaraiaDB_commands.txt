Data types:

1. أنواع البيانات الرقمية (Numeric Data Types):

INTEGER:
  -  TINYINT: أعداد صحيحة صغيرة، تتراوح بين -128 و 127 (أو 0 إلى 255 إذا كانت UNSIGNED).
  -  SMALLINT: أعداد صحيحة، تتراوح بين -32,768 و 32,767 (أو 0 إلى 65,535 إذا كانت UNSIGNED).
  -  MEDIUMINT: أعداد صحيحة، تتراوح بين -8,388,608 و 8,388,607 (أو 0 إلى 16,777,215 إذا كانت UNSIGNED).
  -  INT أو INTEGER: أعداد صحيحة كبيرة، تتراوح بين -2,147,483,648 و 2,147,483,647 
        (أو 0 إلى 4,294,967,295 إذا كانت UNSIGNED).
  -  BIGINT: أعداد صحيحة أكبر، تتراوح بين -9,223,372,036,854,775,808 و 9,223,372,036,854,775,807 
     (أو 0 إلى 18,446,744,073,709,551,615 إذا كانت UNSIGNED).

Float:
  -  DECIMAL أو NUMERIC: أعداد عشرية دقيقة. تُستخدم لتخزين الأعداد التي تحتاج إلى درجة عالية من الدقة مثل القيم المالية.
      يمكنك تحديد الدقة والطول مثل DECIMAL(10,2).
  -  FLOAT: أعداد عشرية تقريبية (ذات دقة أقل من DOUBLE).
  -  DOUBLE: أعداد عشرية تقريبية (ذات دقة أعلى من FLOAT).

2. أنواع البيانات النصية (String Data Types):

  -  CHAR: سلسلة نصية بطول ثابت. على سبيل المثال،
         CHAR(10) سيحجز 10 خانات لكل قيمة، حتى لو كانت تحتوي على عدد أقل من الأحرف.
  -  VARCHAR: سلسلة نصية بطول متغير. على سبيل المثال،
         VARCHAR(255) يمكن أن يحتوي على عدد أحرف يصل إلى 255، ويحجز فقط المساحة المطلوبة فعليًا.
  -  TEXT: سلسلة نصية طويلة. تُستخدم لتخزين كميات كبيرة من النصوص.
  -  BLOB: تخزين البيانات الثنائية (Binary Large Objects)، مثل الصور أو الملفات.

3. أنواع البيانات التاريخية والوقت (Date and Time Data Types):
  -  DATE: تخزين التاريخ بدون وقت، بالتنسيق YYYY-MM-DD.
  -  TIME: تخزين الوقت بدون تاريخ، بالتنسيق HH:MM:SS.
  -  DATETIME: تخزين التاريخ والوقت معًا، بالتنسيق YYYY-MM-DD HH:MM:SS.
  -  TIMESTAMP: مشابه لـ DATETIME، لكنه يتم تحديثه تلقائيًا إلى الوقت الحالي عند إدخال أو تعديل السجل.
  -  YEAR: تخزين السنة فقط، مثل YEAR(4) لتخزين سنة كاملة.

4. أنواع البيانات المنطقية (Boolean Data Types):
  -  BOOLEAN أو BOOL: يمكن أن يحتوي على قيمتين فقط: TRUE أو FALSE.
     في SQL، يتم تمثيل القيم المنطقية عادةً بـ 0 (لـ FALSE) و 1 (لـ TRUE).

5. أنواع البيانات الثنائية (Binary Data Types):
  -  BINARY: سلسلة نصية من البايتات بطول ثابت.
  -  VARBINARY: سلسلة نصية من البايتات بطول متغير.

6. أنواع بيانات أخرى:
  -  ENUM: يُستخدم لتحديد قائمة من القيم المحتملة. على سبيل المثال، ENUM('male', 'female', 'other').
  -  SET: مشابه لـ ENUM، لكنه يمكن أن يحتوي على مجموعة من القيم.

   أنواع البيانات، ما إذا كانت القيم يمكن أن تكون فارغة وما إلى ذلك.

-- Create the 'departments' table:

CREATE TABLE departments (
    id INT NOT NULL PRIMARY KEY AUTO_INCREMENT,  
-- Column 'id' is an integer, not null, auto-incremented, and serves as the primary key

    department_name VARCHAR(100) NOT NULL       
-- Column 'department_name' is a variable character field with a maximum length of 100 characters, and cannot be null
);

-- Create the 'employees' table:
CREATE TABLE employees (
    id INT NOT NULL PRIMARY KEY AUTO_INCREMENT,  
-- Column 'id' is an integer, not null, auto-incremented, and serves as the primary key

    employee_id INT NOT NULL UNIQUE,             
-- Column 'employee_id' is an integer, not null, and must be unique across all rows

    first_name VARCHAR(30) NOT NULL,             
-- Column 'first_name' is a variable character field with a maximum length of 30 characters, and cannot be null

    last_name VARCHAR(30) NOT NULL,             
 -- Column 'last_name' is a variable character field with a maximum length of 30 characters, and cannot be null

    birth_date DATE,                            
-- Column 'birth_date' is a date field

    dept_id INT NOT NULL,                        
-- Column 'dept_id' is an integer and cannot be null

    CONSTRAINT fk_dept_id                       
-- Define a constraint named 'fk_dept_id'

    FOREIGN KEY (dept_id) REFERENCES departments(id)  
-- 'dept_id' in 'employees' references 'id' in 'departments'

    ON DELETE RESTRICT                         
-- Restrict deletion in 'departments' if there are corresponding rows in 'employees'

    ON UPDATE RESTRICT                         
-- Restrict updates to 'id' in 'departments' if there are corresponding rows in 'employees'
);

#####تعريف مفتاح خارجي (FOREIGN KEY)####
المفتاح الخارجي هو مفهوم يُستخدم في قواعد البيانات العلائقية لربط البيانات بين جدولين. هو عمود في جدول واحد يُشير إلى المفتاح الأساسي في جدول آخر.  -
 الهدف الرئيسي من المفتاح الخارجي هو ضمان تكامل الإشارات بين الجداول. هذا يعني أن القيمة في عمود المفتاح الخارجي يجب أن تتطابق مع قيمة في عمود المفتاح الأساسي في الجدول المرجعي أو تكون NULL.
